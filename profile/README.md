# NSTUDIOS

**Infinite ideas, limitless creation.**

NSTUDIOS is a software and product studio building practical systems for developers, creators, and small businesses. We work across web platforms, backend services, infrastructure automation, creative tools, and embedded/IoT experiments.

Our public GitHub exists to show how we build: clear code, useful documentation, repeatable systems, and production-minded engineering.

## What we build

- **Developer tools** — templates, utilities, and examples that help teams ship faster.
- **Web platforms** — frontend and backend patterns for modern product development.
- **Infrastructure systems** — automation, deployment, storage, and self-hosted service experiments.
- **Creative technology** — animation, UI systems, game/app experiments, and creator-first workflows.
- **Embedded and IoT** — ESP32, robotics, simulation, and hardware-connected software.

## Open source focus

We publish selected projects that are useful outside of NSTUDIOS and safe to maintain in public. Our goal is not to open-source everything. Our goal is to share practical work that developers can learn from, build on, or adapt.

Current public areas include:

- **SpiderApp Project** — UI simulation and embedded tooling experiments for ESP32-based systems.
- **NSTUDIOS web and tutorial projects** — public examples, landing-page work, and learning material.
- **Infrastructure and storage experiments** — selected public research around self-hosted systems and object storage workflows.

## Engineering principles

We care about:

- Clear README files and setup instructions
- Small, understandable project structure
- Secure defaults and no committed secrets
- Useful examples over unnecessary complexity
- Maintainable code over hype-driven architecture
- Documentation that explains decisions, not just commands

## Contribution model

Most NSTUDIOS repositories start as internal experiments or focused templates. When a project is ready for outside use, we add contribution guidance, issues, labels, and a documented roadmap.

For now, the best way to contribute is to open an issue with:

- A clear problem statement
- Steps to reproduce, when relevant
- Expected behavior
- Environment details
- A focused proposal or pull request
